## Findings and review observations

1. **Opaque literal braces could crash or change accepted panel values.** Previously `tr()` unconditionally formatted even unknown no-argument strings. Accepted fare `service_type="Special {class}"` and accessibility `feature="Lift {A}"` raised `KeyError`; `Station {{name}}` changed literal braces. Independent focused probes demonstrated the regression. The implementation now leaves no-argument strings literal, and panel service/feature values use guarded `field_label()`. The same original inputs now survive exactly in English, Hindi and Hinglish.
2. **Unsupported route enum metadata broke unknown-explanation fallback.** `valid_reply()` accepts route rows containing a non-string `mode`. Previously Hindi/Hinglish `reply_text()` performed an unhashable enum lookup before checking whether the factual prefix matched, raising `TypeError` even for an unknown explanation. The implementation now guards non-string enums and refuses to localize a factual prefix using unsupported mode/feature metadata. Original qualified text survives both unknown-tail and backend-shaped-prefix cases. No invented localized fact replaces it.
3. **Unsubmitted form/composer drafts require stable browser widget identity.** Initial AppTest coverage used `.set_value(draft).run()`, which sends widget state to the test runner and cannot establish preservation of a genuinely browser-only form draft. This limitation was reported before the primary reproduced real draft loss. Current revision field label and composer placeholder are stable trilingual strings, while a separate caption and submit label are localized. Within one clarification turn, the field key and pending-question default also remain constant across language changes. Source review and identity assertions support the correction; the primary's native-browser retest is the live evidence, not this review's pure probes.
4. **Previous revision text was observed while a new clarification render was settling.** In the primary's native-browser sequence, Hindi H08 briefly showed H07 in the revision field. The bulk helper then waited only for new user/reply nodes, so this observation does not establish a persistent defect. The primary strengthened readiness to require the latest revision value to equal the current question. The per-turn key `revision_text_{len(messages)}` remains intentional robust handling, supported by the primary's two red/green AppTest cases. Independent review confirms `_submit` appends a user/reply pair before the next render: a language-only rerun leaves the key unchanged, while a new clarification advances the key and uses the new `pending_query` as its default. Repeating the identical question still advances the key. The cases cover both a different and an identical repeated question; their final-input assertion addresses the primary-reported AppTest 1.44 stale form-node artifact. This reviewer did not independently run AppTest or claim that artifact as live-browser evidence. This observation is not counted as an additional confirmed persistent bug; the language-switch draft loss in finding 3 was definitely reproduced by the primary.

## Review assessment

The language radio is an exclusive native control with explicit English/Hindi/Hinglish names and a stable session key. The theme gives the radio choices minimum 44px height and a focus-within outline; actual layout/focus is left to the primary browser evidence. Known status labels, explanations, panel headings, source/date/caveats and missing-input labels are localized. Unknown explanations remain verbatim with an explicit localized label. Factual prefix localization requires an exact match to the original backend rendering; canonical names, route identifiers, currency, times, source identifiers and dates are preserved.

Changing language re-renders saved replies and does not itself submit a question. `_submit` still sends the original query, with no language-dependent model input, alias or classifier processing. Explicit starter questions are sent verbatim. The turn-based revision key is appropriate for the current append-only chat history; future history replacement/truncation would require rechecking that identity assumption. Backend recognition/source limits documented by the 48-case baseline remain limits; translating a wrong-family reply does not make that goal successful.

No additional actionable defect was found in this bounded code/focused-probe review after the fixes. This is not a full-suite or complete product pass. Real browser draft retention, all three starter activations, localized rendering/glyphs, responsive behavior, browser console inspection and cleanup remain primary-owned verification responsibilities.
