## Keyboard and table interaction

- Starter, chat Enter, keyboard send and full-question revision submission worked. Revision button focus showed a 2 px oxblood outline.
- The send icon has no accessible name (empty text, no aria-label or title). This is a low accessibility finding. Keyboard focus still has a visible 2 px oxblood outline on the chat-input container; a missing focus ring is **not** claimed.
- Table search for Airport reported three matches, enabled previous/next navigation, accepted Next and closed successfully. After filling, the search textbox was unnamed in the accessibility snapshot despite its initial “Type to search” name; record this as an accessibility limitation, not a search failure.
- Table columns control hid and restored the source column. Source column was restored before export. Fullscreen opened and closed successfully.
- Sorting was not systematically verified. An incidental header sort occurred while targeting a toolbar control, so the IIT CSV retains the displayed source-descending order rather than promising distance order.
- The native Download as CSV control was activated, but the download event could not be verified: the automation call timed out and unexpectedly blocked for about 314 seconds despite a requested 10-second event timeout. This is a tool observation, not proof that the application export is broken.

## Layout evidence and limits

The parchment background, oxblood accents, serif headings, sidebar and source-backed cards remained visible in the desktop captures. A long six-pair history remained usable. Default screenshots are 1280×720. Requested responsive viewports were 1440×1000, 1024×768 and 768×1024; viewport overrides were temporary testing controls.

At the captured 768×1024 CSS viewport, `innerWidth=768`, `innerHeight=1024`, document and body scroll widths were 768. The h1 rectangle was x=16/y=88/width=736/height=71; the expanded sidebar occupied x=0/y=0/width=336/height=1024. The sidebar was an open overlay at that width, not evidence of an unclosable drawer. Closing/reopening it was not completed.

Native IAB screenshot dimensions do not consistently equal the overridden CSS viewport: desktop-history is 1440×810, tablet-1024 is 1024×576, tablet-768 is 768×576. They are partial/scaled surface evidence, not full-height responsive proofs. Fullscreen table capture is 1440×1000. A subsequent explicit page screenshot attempt timed out before producing a file.

After that timeout the browser inventory became empty. Rebinding the selected browser and creating one fresh temporary IAB tab both failed because no browser was available. Thus phone-width coverage, mobile queries, drawer controls, virtual keyboard behavior and final primary-tab/viewport cleanup could not be verified. The last requested override was 768×1024; no claim is made that it persisted or was reset after the connection disappeared. The agents had already closed their own tabs, and their viewport was unchanged. User-owned tabs were not deliberately modified or closed.
